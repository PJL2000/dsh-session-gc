# dsh-session-gc

[English](README.md) | **简体中文**

用于 dsh-tui 的会话历史手动清理工具。浏览所有已存储的对话，标记要删的，
然后删除 —— **钉选（星标）会话默认受保护**。

```
/delhistory
```

## 为什么需要它

`/resume` 能列出会话，非 DSH 后端也有 `Ctrl+D` 删除，但 DSH 会话在选择器里
根本没有删除入口：那个按键处理被 `!dshBackend` 挡住，在 DSH 下按了没反应。
本插件补上这个缺口，而且不用改 TUI 的构建产物（改了会被 `/update` 覆盖）。

它还存在，是因为有一类失败值得专门设计来防：一次批量删除清空了整个历史，
连星标会话一起没了，原因是保护名单通过一个脚本错误静默塌缩成了空集。这里的
每个设计选择，目标都是让这类错误**不可能发生**，而不只是"不太会发生"。

## 按键

| 按键 | 动作 |
| --- | --- |
| `↑` / `↓` | 移动光标 |
| `Space` | 标记 / 取消标记当前行 |
| `a` | 标记当前计划会删除的所有行 |
| `d` | 删除已标记行（询问 `y` / `n`） |
| `p` | 切换钉选保护（询问 `y` / `n`） |
| `r` | 重新扫描 |
| `Esc` / `q` | 离开界面 |

## 保护机制

1. **钉选会话保留，除非你显式解除保护。** `p` 在钉选行变为可选之前先要求确认，
   开启期间页脚会持续提示。
2. **活跃会话永远不能删。** 它们被排除在计划之外，执行时还会再拒一次。ID 从
   `channel.sessionId` 解析；调用方忘了传时，从 TUI 自己的 `last-run.json` /
   `session-mounts.json` 探测，所以这个防护不依赖"有人记得传参数"。开两个 TUI
   窗口就有两个活跃 ID，**全部**受保护。空的 `channel.sessionId`（TUI 在没有
   挂载会话时确实会写 `""`）表示"没有"，而不是"空会话"。
3. **读不了的 pin 文件保护不了任何东西，于是它保护一切。** 格式错误或不可读的
   `session-pins.json` 会显示错误并列出空列表，而不是给出一个看起来"没设保护"
   的列表。同样地，格式正确但条目全部不可用也算损坏：零个可用 pin 是数据损坏，
   不是空 pin 集。
4. **删除前每个计划都会对照当前 pin 集重算。** 计划携带它构建时的 pin 快照 ——
   包括那些会话目录已经不存在的 pin，因为孤儿 pin 仍然是保护。若构建计划之后
   pin 集变了（另一个窗口钉了东西），删除会拒绝并要求重建计划。
5. **逐个目标重新验证包含关系。** 解析符号链接后仍不位于已知 sessions 根目录
   内的目录会被拒绝。
6. **逐会话删除并如实汇报。** 中途失败会被列出，不会被吞掉。

## 测试

纯 Node，无测试框架：

```sh
node test/core.test.mjs         # 发现、计划、全部删除防护
node test/guard-drill.mjs       # 对一次性存储逐个攻击每道防护
node test/plugin.test.mjs       # 入口形态、注册、命令行为
node test/scene-render.test.mjs # 选择器，由微型渲染器驱动
node test/inspect-real.mjs      # 对真实存储的只读报告
```

`inspect-real.mjs` 不删除任何东西。对真实数据验证时先跑它：它会打印每个会话、
哪些会保留、哪些会删除，以及孤儿 pin（目录已不存在的钉选 ID）。

`test/fixtures/make-fixtures.mjs` 在系统临时目录里构建一个一次性的假会话存储，
并打印指向它的 `DSH_HOME` / `DSH_TUI_HOME` 值，这样你可以驱动真实选择器而不
冒真实历史的风险。

## 安装

```sh
dsh plugin --profile <profile> add <path-or-package>
```

本包声明了 `dsh.bundle.patch`，所以安装会把它追加到 profile 的
`dsh.profile.bundles`，并由 `cordis.patch.yml` 挂载。之后重启 dsh-TUI ——
命令在启动时注册。

## 安全模型

本插件会删除 sessions 根目录下的目录，所以它按"其他所有防护最终都会出错"来设计：

- pin 是**保护键**，不是路径。永远不可能命名目录的值也会被保留为 pin 而不是
  丢弃，因为丢一条 pin 就会在无人察觉的情况下缩小保护集。
- `planDeletion` 从不从它列出的行推导 pin 快照。因此孤儿 pin（已钉选、目录已
  消失）仍能阻止防护把文件误读成"什么都没钉"。
- 空的 `channel.sessionId` 被视为**缺失**，因为 TUI 在没有挂载会话时确实会写
  `""`。把它当成显式 ID 会让活跃会话探测失效。
- 出现下列情况时删除会被拒绝：pin 文件在计划构建后变化、任何钉选 ID 进入删除
  列表、任何活跃 ID 进入删除列表，或某个目标解析到已知 sessions 根目录之外。

## 目录结构

| 文件 | 职责 |
| --- | --- |
| `lib/core.js` | 发现、pin 读取、计划、带防护的删除。不含 React 与 cordis —— 可用纯 Node 单元测试。 |
| `lib/scene.js` | 全屏选择器。渲染 `core.js` 的产物，并把按键转回给它。 |
| `lib/index.js` | 插件入口：注册 `/delhistory` 与场景。TUI 接缝缺失时保持惰性。 |
